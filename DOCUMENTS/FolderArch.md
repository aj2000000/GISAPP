# BrahmaxisGIS Project Folder Architecture & Subfolder Specification

## Executive Overview
This document provides a comprehensive architectural breakdown of the directory and file organization inside the **BrahmaxisGIS** codebase. The project is designed following **Clean Architecture**, **SOLID Principles**, and strict separation of concerns to decouple core domain logic, spatial data persistence, rendering engines (MapLibre Native C++), and the Qt Presentation UI layer.

---

## 1. Top-Level Directory Structure

```text
GISAPP/
├── DOCUMENTS/                   # Architecture design specifications & system documentation
├── SAMPLEDATA/                  # Sample tracks (tracks.csv) & geospatial benchmark datasets
├── config/                      # Persisted runtime configurations (published_layers.json)
├── build/                       # Build artifacts generated by qmake & make
├── src/                         # Application Source Code
│   ├── main.cpp                 # Application entry point & Qt app lifecycle initialization
│   ├── controllers/             # View Controllers & Tool State Managers
│   ├── core/                    # Core Domain, Storage, Models, & Background Services
│   ├── layers/                  # Engine-Agnostic Layer Tree & MapLibre Adapter
│   ├── map/                     # Low-Level Map Engine OpenGL Widget Integration
│   ├── publishing/              # GDAL/VRT Processing, Layer Publishing & Local Tile Server
│   ├── tools/                   # Interactive Map Tools (Pan, Measure)
│   └── ui/                      # Presentation Layer (Qt Widgets, Dialogs, Sidebars)
├── GISAPP.pro                   # Qt QMake Project Configuration
└── startGis.sh                  # Execution & environment bootstrap script
```

## 2. Deep Dive: `DOCUMENTS/` Folder
* **Purpose**: Serves as the central repository for system engineering design documents, low-level design patterns, API specifications, and architectural documentation.
* **Why this folder was created**: Keeps project documentation separate from executable source code, allowing team members, system architects, and maintainers to inspect system specifications without cluttering `src/`.
* **Files inside `DOCUMENTS/`**:
  - `Arch.md`: Comprehensive system architecture and module relationship specifications.
  - `archv4.md`: Version 4 architectural evolution details.
  - `FolderArch.md`: (This document) Detailed folder and subfolder breakdown and design rationale.

## 3. Deep Dive: `src/` Subfolders

### 3.1. `src/core/` (Pure Domain & Infrastructure)
* **Purpose**: Contains the core business logic, entity models, database persistence, background task pipelines, and event notification engine. This folder is independent of Qt GUI views.
* **Subfolders & Rationale**:

#### `src/core/models/`
- **Purpose**: Defines pure domain entities and geometric containers.
- **Files**:
  - `TrackRecord.h/.cpp`: Represents a tactical track entity with 20 schema attributes (ID, lat, lon, altitude, speed, heading, affiliation). Implements GeoJSON serialization (`toGeoJsonFeature()`).
  - `IGisEntity.h` & `IGisGeometry.h`: Top-level interface definitions for all GIS entities (Points, Polylines, Polygons, Symbols).
  - `GeoCoordinate.h`: Encapsulates high-precision WGS84 geographic coordinates.
- **Why decoupled**: Models store entity attributes without any database (SQL) or UI widget dependencies.

#### `src/core/database/`
- **Purpose**: Manages low-level SQLite database lifecycle and schema creation.
- **Files**:
  - `DatabaseManager.h/.cpp`: Singleton wrapping Qt SQL (`QSqlDatabase`), initializing `gis_app_database.sqlite` tables and spatial indexes.

#### `src/core/repositories/`
- **Purpose**: Implements the Repository Pattern for data access abstraction.
- **Files**:
  - `ITrackRepository.h`: Interface for track persistence operations.
  - `TrackRepository.h/.cpp`: Executes SQLite queries (`SELECT`, `INSERT`, `UPDATE`) and emits `tracksUpdated()` signals for reactive updates.

#### `src/core/services/`
- **Purpose**: Business service integrations.
- **Files**:
  - `CsvTrackIngestor.h/.cpp`: Ingests external track datasets (`tracks.csv`), validates coordinate bounds, and persists records into SQLite.
  - `MapLibreTrackAdapter.h/.cpp`: Bridges the `TrackRepository` to MapLibre Native by serializing active tracks into disk-backed GeoJSON (`tactical_tracks.geojson`) and calling `m_map->updateSource()`.

#### `src/core/tasks/`
- **Purpose**: Asynchronous background thread execution.
- **Files**:
  - `BackgroundTaskManager.h/.cpp`: Manages thread pools for long-running operations.
  - `GoogleSatDownloaderTask.h/.cpp`: Asynchronously downloads and tiles online satellite imagery.

#### `src/core/notifications/`
- **Purpose**: System-wide event observation and toast notification handling.
- **Files**:
  - `NotificationManager.h/.cpp`, `NotificationFactory.h/.cpp`, and Strategy implementations.

---

### 3.2. `src/layers/` (Layer Management & GIS Engine Abstraction)
* **Purpose**: Manages map layer hierarchies, group trees, layer visibility, and GIS engine decoupling.
* **Why this folder was created**: Provides an engine-agnostic layer management model, ensuring that the UI tree view operates on generic layer adapters without hardcoding MapLibre API calls everywhere.
* **Files & Rationale**:
  - `ILayerAdapter.h`: Abstract contract for any map layer (opacity, visibility, re-insertion, extent).
  - `MapLibreLayerAdapter.h/.cpp`: Concrete MapLibre engine implementation of `ILayerAdapter`.
  - `LayerManager.h/.cpp`: Central manager maintaining layer lists and active layer states.
  - `LayerTreeModel.h/.cpp` & `LayerTreeNode.h/.cpp`: `QAbstractItemModel` implementation driving the hierarchical Layer Management Tree in the UI.
  - `TacticalLayerProvider.h/.cpp`: Bootstraps default operational base maps, radar zones, and track layers on startup.

---

### 3.3. `src/publishing/` (Map Publishing & Local Tile Server Engine)
* **Purpose**: Ingests external raster imagery (GeoTIFF, DSM) and vector files (Shapefile, GeoJSON), generating GDAL VRT catalogs and streaming tile sources.
* **Why this folder was created**: Separates complex GIS data transformation and tile serving from basic UI rendering.
* **Files & Rationale**:
  - `IPublisherStrategy.h`: Strategy pattern contract for dataset publishers.
  - `RasterLayerPublisher.h/.cpp`: Processes GeoTIFF files using GDAL, generating VRT catalogs and registerable tile endpoints.
  - `VectorLayerPublisher.h/.cpp`: Converts vector Shapefiles into MapLibre-compatible sources.
  - `LocalTileServer.h/.cpp`: Threaded local HTTP tile server serving raster tiles directly to MapLibre.
  - `LayerRegistryManager.h/.cpp`: Manages disk persistence of published layers (`config/published_layers.json`).
  - `LayerPublishingService.h/.cpp` & `PublisherFactory.h/.cpp`: Orchestrates layer publication workflows.

---

### 3.4. `src/map/` & `src/controllers/` (Engine Viewport & Navigation Controllers)
* **Purpose**: Encapsulates low-level map rendering widgets and camera state controllers.
* **Files & Rationale**:
  - `src/map/MapLibreWidget.h/.cpp`: OpenGL widget hosting `QMapLibre::Map`.
  - `src/map/OverlayWidget.h/.cpp`: HUD overlay for displaying screen coordinates and map scale.
  - `src/controllers/MapController.h/.cpp`: Camera navigation controller (zoom, pan, center coordinate).
  - `src/controllers/ToolManager.h/.cpp`: Coordinates active map tool states (e.g. Pan vs Measure).

---

### 3.5. `src/tools/` (Interactive Canvas Tools)
* **Purpose**: Contains stateful user map tools.
* **Files & Rationale**:
  - `MeasureTool.h/.cpp`: Calculates geodesic distances and angles between mouse click points on the canvas.
  - `PanTool.h/.cpp`: Standard map panning and cursor tool.

---

### 3.6. `src/ui/` (Presentation & Qt Widget Views)
* **Purpose**: Contains all Qt Widget UI components, sidebars, dock panels, and modal dialogs.
* **Why this folder was created**: Keeps GUI layout and user event handling isolated from backend domain services.
* **Subfolders & Files**:
  - `mainwindow.h/.cpp`: Main application window shell hosting toolbars, dock widgets, and central map area.
  - `HeaderBar.h/.cpp`: Top navigation toolbar.
  - `LeftSidebar.h/.cpp`: Main tool palette sidebar.
  - `RightToolPanel.h/.cpp`: Layer & feature property inspector.
  - `TacticalStatusBar.h/.cpp`: Real-time status bar showing FPS, coordinates, and memory usage.
  - `ui/tracks/`: `TracksTableDialog` & `TrackTableModel` for tabular display and search of tactical tracks.
  - `ui/layertree/`: `LayerTreeFloatingWidget` & `LayerTreeView` providing floating UI layer hierarchy management.
  - `ui/publishing/`: `PublishLayerDialog` & `GroupManagerDialog` for user layer publishing.
  - `ui/download/`: `DownloadSatImageryDialog` for satellite imagery download configuration.
  - `ui/tasks/`: `BackgroundTaskDialog` for monitoring background threads.
  - `ui/notifications/`: Notification center and toast widgets.

## 4. Architectural Summary

| Layer | Responsibility | Key Classes |
| :--- | :--- | :--- |
| **Domain Models** | Entity data structures & GeoJSON serialization | `TrackRecord`, `GeoCoordinate`, `IGisEntity` |
| **Persistence** | SQLite storage & CRUD repository access | `DatabaseManager`, `TrackRepository` |
| **Services** | CSV ingestion & MapLibre track sync | `CsvTrackIngestor`, `MapLibreTrackAdapter` |
| **Layers** | Layer tree model & engine abstraction | `LayerManager`, `MapLibreLayerAdapter`, `TacticalLayerProvider` |
| **Publishing** | GDAL processing & local tile server | `RasterLayerPublisher`, `VectorLayerPublisher`, `LocalTileServer` |
| **Presentation** | Qt Widget views & user interfaces | `mainwindow`, `TracksTableDialog`, `LayerTreeFloatingWidget` |
